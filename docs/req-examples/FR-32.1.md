# FR-32.1 — Outcome of a flow (TS)

```ts
// POST /orders
async function createOrder(req: Request, res: Response) {
  const order = await orders.place(req.body);   // OrderService.place → OrderRepository.save (DB)
  await invoices.issue(order);                  // InvoiceService.issue → InvoiceApiClient.post (fetch: HTTP)
  res.status(201).json(order);
}

class InvoiceService {
  async issue(order: Order) {
    try {
      await this.api.post(order);
    } catch (e) {
      await this.outbox.enqueue(order);         // OutboxPublisher.enqueue → amqplib (MQ), only on the error branch
    }
  }
}
```

Under the tag `POST /orders`: `DB · HTTP → 1 API · MQ`. The hover card lists `DB via OrderRepository`,
`HTTP via InvoiceApiClient`, `MQ via OutboxPublisher`, each with its library call. MQ is counted though it runs only
in the catch: the outcome covers error branches too, and whether the user's diagram is expanded makes no difference.
